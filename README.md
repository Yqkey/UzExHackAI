# Агент по сделкам биржи (RU + UZ)

Веб-сервис и Telegram-бот, отвечающие на вопросы по реестру сделок (500 000 сделок, 03.01.2022–30.10.2026) строго по данным.

## Быстрый запуск
```bash
pip install -r requirements.txt
python build_db.py /путь/к/csv        # собирает data/exchange.duckdb (~20 МБ, 1 минута); готовый файл уже в архиве
cp .env.example .env              # впишите GEMINI_API_KEY (PROVIDER=gemini по умолчанию; PROVIDER=anthropic — Claude)
python verify_data_layer.py /путь/к/csv   # сверка витрины с pandas по сырым CSV
python selftest.py                    # пробный прогон вопросов
uvicorn web:app --host 0.0.0.0 --port 8000      # веб-сервис
TELEGRAM_TOKEN=... python bot.py                # Telegram-бот
```
Публичная ссылка: Render / Railway / Fly.io по Dockerfile (переменная ANTHROPIC_API_KEY), либо локально + `cloudflared tunnel --url http://localhost:8000`.

## Описание решения (для формы)
**Архитектура.** Text-to-SQL агент: LLM (Claude) с двумя инструментами — `sql` (только SELECT/WITH, DuckDB в режиме read-only) и `find_entities` (нечёткий поиск компаний, брокеров, товаров, марок; кириллица/латиница, кавычки, регистр). Модель не отвечает «из головы»: каждое число берётся из результата SQL-запроса.

**Подготовка данных.** 5 CSV сделок + контракты + участники + брокеры + курсы собраны в DuckDB и объединены в витрину `v_deals` (1 строка = 1 сделка): типизированные даты и суммы, сумма в сумах и USD по курсу на дату сделки, цена и объём за единицу, названия продавца, покупателя и брокеров, регион на русском и узбекском. Описание товара в реестре заполняет продавец, поэтому названия нормализованы: 230 вариантов → 41 канонический товар, сорт, класс, марка, размер и тип приведены к единому виду (1 сорт = 1-сорта = I сорт = первый сорт; в/с = высший). Проверено по цене и коду ТН ВЭД, что варианты — один товар.

**Защита от выдумок.** (1) Промпт: нет данных → прямо сказать «в данных ответа нет»; неоднозначность → назвать выбранное прочтение. (2) Программная проверка: каждое число в ответе сверяется с результатами запросов; если числа нет — модель обязана пересчитать SQL-запросом или убрать его, иначе в ответ добавляется предупреждение. (3) SQL только на чтение. (4) Справочник значений (товары, регионы, статусы) подставляется в промпт из самой базы.

**Бизнес-правила.** Аннулированные сделки («не состоялась») исключаются из сумм, объёмов и рейтингов с явной пометкой, и рядом даётся значение «с аннулированными»; USD не смешивается с сумами; объёмы в разных единицах (тонна/литр/кг) не складываются; регион = склад продавца.

**Как проверяли.** `verify_data_layer.py` — 37 независимых сверок витрины с расчётом по сырым CSV в pandas (суммы по годам, счётчики по регионам и статусам, топ-продавцы, объёмы): расхождений 0. Цикл агента и проверка чисел протестированы на подменённой LLM. `selftest.py` — набор вопросов на RU/UZ, включая «ловушки» (нет данных, дата вне периода).

**Интерфейс.** Ответ + строка «Основание» + SQL под спойлером (видно, на чём основан ответ), язык ответа = язык вопроса, время ответа ограничено 80 секундами.
